## Context and Orientation

## Idempotence and Recovery

Вызовы сравниваются по ключу и полезной нагрузке. Повтор команды с прежним ключом и изменёнными параметрами возвращает Conflict. Доменный сервис также отслеживает уникальность смерти по RunId и SpawnId, зачистки по RunId и checkpointIndex, покупки и расходуемого предмета по их собственным ID. Если запись не прошла, повтор использует исходные параметры и ключ. Новый осознанный выбор получает новый ActionId.

## Interfaces and Dependencies

IProgressionSession возвращает ProgressionResult для изменяющих команд и ProgressionSnapshot для чтения. ProgressionCommandKey связывает RunId с ActionId. ProgressionCheckpoint связывает комнату стадии с индексом записи. ProgressionTransitionPoint описывает вход, а ProgressionNpcSnapshot связывает его с услугой и видимым предметом. Контракт компилируется в Game.Runtime, проверяется Game.Tests.EditMode и использует уже существующий Game.Core.RunOutcome.

ICityProgressionSession добавляет EnterStage и CollectSupply. CityProgressionSession.BindCombat ожидает IProgressionCombatSink. Этот интерфейс расширяет IRunResourceSink идентификатором и видом активного оружия и установкой временных боевых множителей. Для штатного игрока его реализует PlayerCombatFacade.

ISaveRepository предоставляет Load и TryCommit(expectedRevision, candidate). В JsonSaveRepository путь передаёт вызывающий код. Для разработки он указывает Game/LocalState, тесты создают папки Game/TestResults/Saves. CityProgressionSession принимает репозиторий в конструкторе и публикует SelectedWeaponId для Home и StartingWeaponId для боевой сцены.
