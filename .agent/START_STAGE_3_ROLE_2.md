## Предварительный интерфейс общей границы

У1 фиксирует полные конструкторы и неуспех в `Game/Docs/S3_01_LAYOUT_CONTRACT.md`. Предварительный v0.1 одинаков в двух личных планах.

В namespace Game.Generation метод `RunGenerator.Generate(int seed, StageCatalog catalog, int generatorVersion, int contentVersion)` возвращает GenerationResult с Layout, UsedFallback и Diagnostic. RunLayout содержит Seed, GeneratorVersion, ContentVersion и ровно5 SegmentLayout, каждый с Index1..5 и ModuleId. Первые4 — Combat, пятый — Boss. Обычные модули могут повторяться. Entry/Rest существуют вне обязательной пятёрки.

StageCatalog содержит ModuleDescriptor с Id, Kind, Width/Height, Walkable длиной Width*Height, Entry/Exit и SpawnCells типа Cell(X,Y). Kind — Entry, Combat, Rest, Boss. Индекс клетки y*Width+x. Данные описывают пространство для центра актора с учётом радиуса. Ваш Unity-адаптер экспортирует описания из собственных ассетов и загружает модуль по Id. Генератор не создаёт GameObject и не загружает сцены. LayoutValidator.Validate(layout,catalog) возвращает ValidationResult с IsValid/Reasons, проверяет путь по4 соседям от входа ко всем обязательным точкам и выходу.

Начальные Id — street_entry, street_a, street_b, street_c, street_rest, street_boss. Переход между модулями раздельный, вход и выход не обязаны совпадать в мировых координатах. Это выбор последовательности модулей, физически непрерывная карта за границами задачи. Максимум20 попыток подбора, затем проверенная схема a,b,c,a,boss. Невалидные данные/fallback приводят к читаемой ошибке до запуска боя. Полицейский с радиусом2 требует свободной большой площадки и отдельной геометрической проверки.

## Как выполнять запросы

Один запрос — один проверяемый результат. Средний уровень рассуждения подходит аудиту/статусу, высокий — переходам, состояниям и интеграции. Модель выбирается пользователем в клиенте. При диагностике сохранять точный сценарий, diff, лог и неуспешный XML.

По каждому шагу фиксировать базовый/hash, явные файлы, API, реальные discovered/executed/passed/failed/skipped/inconclusive и новые XML. NOT RUN не заменять числом0 failed. Проверки проходить через настоящий Bootstrap и обычные кнопки. Собственный локальный коммит делать явными путями после diff, scratch/Library/отчёты/сборки не добавлять автоматически. Путь Unity на Windows уже разрешён в этой сессии, на других машинах использовать их разрешённый путь.
