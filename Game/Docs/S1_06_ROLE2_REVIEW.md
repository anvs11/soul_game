## Результат ревью

Блокер У1 — отсутствие настоящих HudPresenter/ArenaController в основной сцене — закрыт. CombatSandbox содержит настоящего игрока и три экземпляра боевых заготовок, один TargetRegistry; используются AutoAimSelector.Configure и SandboxEnemy.Initialize. Исходные prefab и контракт v0.1 не заменены. Повтор создаёт новые объекты и RunId, а не переиспользует состояние прежней сцены.

Проверены ресурсы оружия, отказ полного пула без списания патрона, повторное использование пули, стена перед целью, выбор видимой цели и уникальные смерти. Новый удар зомби имеет подготовку, проверку дальности/сектора и отбрасывание только при принятом уроне. Пассивное столкновение героя и зомби не толкает героя. Стены ограничивают обычное движение и отбрасывание; реальные размеры collider в сцене исправлены. Крупная локация, радиус обнаружения, укрытия, взрывные бочки и несколько типов AI в эту передачу не входят.

ArenaController подписывается/отписывается от смерти, взаимодействия и паузы. Выгрузка врага не считается убийством. Выход доступен после трёх уникальных смертей и только в его зоне. RunCoordinator сохраняет отложенное разрешение результата с приоритетом Defeat. Смерть блокирует повторное включение боя; повторный результат не создаёт второй переход. Меню результата — отдельное состояние Home, без изменения контракта фаз.

Пауза сохраняет PauseRequested, останавливает scaled-таймеры боя, сбрасывает удерживаемый виртуальный ввод. Возврат/новый старт восстанавливают timeScale=1. Экранные элементы используют существующие gamepad binding Player.inputactions: leftStick, buttonSouth, buttonNorth, buttonWest, start. У действий боя нет отдельного параллельного обработчика клавиатуры. EventSystem с InputSystemUIInputModule один; UI navigation/submit отключены для кнопок меню, поэтому атака не нажимает выделенную кнопку. Safe Area применяется к HUD и экранным контролам.

## Обнаруженный дефект и исправление

Первый настоящий Windows exe выявил NullReferenceException в ProjectilePool.OnDestroy: Unity при выгрузке могла сначала уничтожить отдельный корневой контейнер с неактивными пулями, затем владелец ObjectPool.Clear пытался прочитать gameObject уже уничтоженной пули. Callback уничтожения теперь проверяет Unity-null. Регрессионный DestroyedReturnedProjectileDoesNotBreakPoolOwnerTeardown воспроизводит этот порядок, сохраняя прежние проверки попаданий/ресурсов. Standalone runner дополнительно считает Error/Exception/Assert из общего лога: успешные переходы при исключениях больше не дают passed=true. Первый прогон с исключениями не принят.

## Изменение Foundation-проверок

FoundationFlowTests больше не ищет удалённый из CombatSandbox тестовый EmptyArenaScreen. Сценарий десяти переходов теперь завершает реальную арену: закрытый выход, три смерти, отказ взаимодействия издалека, выход в зоне, двойное взаимодействие и новые сцены. Ожидаемый исход этого сценария изменён с Abandoned на Victory явно. Тест конфликта результата теперь сочетает Victory с настоящей смертью героя вместо второго прямого вызова FinishRun. Сохраняются проверки единственных сервисов, выгрузки старых объектов и новых RunId. Abandoned и двойной выход домой дополнительно проверяет BoundaryPauseTouchTests. Старые XML остаются историей, а не текущей приёмкой.
