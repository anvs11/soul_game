# Stage 4 — фиксация среза 1-1

## Игровая приёмка

19 ноября 2026 пользователь подтвердил работу кувырка, плотность обычных зомби и общую сложность 1-1. По результатам этой проверки все 6–8 обычных врагов теперь появляются одним набором на комнату, дробовик наносит на 12,5% больше, прямое попадание медсестры связывает на 1 с, после комбо у неё пауза 2,5 с. Окно проверяется даже при неподвижном герое в радиусе выстрела. Оглушение туманом длится 2 с.

В Bootstrap откройте Home и выберите «Играть 1-1». Ввод seed воспроизводит встречи при одинаковой версии каталога. Три обычных типа распределяются по безопасным точкам. В финале три экземпляра двух видов, успешные призывы обязательны для зачистки, награды принадлежат текущей попытке. После четырёх зачищенных комнат доступен один портал. Пожелания по битым машинам, шинам и бочкам закреплены в [заметках по карте](S4_MAP_FEEDBACK_2026_11_18.md).

## Проверка данных и сборки

Unity 6000.3.28f1. Отчёты Windows Editor находятся в `Game/TestResults/s4-final-20261119`. Полные `EditMode.xml` и `PlayMode.xml` прошли 149/149 и 129/129 соответственно, оба exit 0. Проверены окна ответа медсестры, одновременная активация обычной комнаты, закрытые двери до последнего врага и десять забегов с победой, поражением и выходом во время боя. В полный прогон включена регрессия прежних стадий в Editor. Экспорт `S4_FIXED_MAP_V3_COMBAT.json` содержит 1920 достижимых клеток, 24 сертифицированные позиции призыва и SHA-256 `dca5b0ae5590310af574c7893c0fb519e9537b4ef158cd93f885e9b96913a1a6`. Сравнение текущего каталога и экспорта для seed 0–999 дало 1000 успехов, 0 отказов, 0 fallback. Каталог V3, геометрия V1. Два предыдущих экспорта V2 остаются пригодными для воспроизведения своих версий.

Обе команды сборки доступны в меню Game → Build. Для Windows `Game.Editor.BuildCommands.BuildStage4Windows`, для Android `Game.Editor.BuildCommands.BuildStage4Android`. Список сцен начинается с Bootstrap, включает Home, боевые сцены прежних стадий и `Stage4StreetMap.unity`. Тренировочные и диагностические сцены, открываемые отдельно в редакторе, в список не входят. Builder пишет отдельный `build-report.json` рядом с Player в `Game/Builds/Stage4/<platform>/<buildId>/`.

Windows build `s4-20261118-222859-e0b8185f`, GUID `e9a2c51229964f8f889d59e7ae3a3705`, Succeeded, 0 ошибок и 0 предупреждений в BuildReport. В отдельном Player подтверждены запуск из Bootstrap, вход в 1-1 с seed 42, HUD с 8+16, мини-карта, экранный кувырок, смена оружия, пауза и экран результата при выходе. `manual-player.log` находится рядом с BuildReport. Завершение боя, подборы и портал проверены PlayMode. Android Player и проверка на устройстве остаются открытыми.

## Открытые условия

Повторный ручной бой после изменений, независимая приёмка У1, проверка на физическом Android и измерение производительности устройства остаются отдельными условиями. На Android проверить движение и кувырок двумя пальцами, Safe Area, сворачивание и сбор предмета после возврата.

При закрытии Windows Development Player DX12 повторилось прежнее предупреждение `GarbageCollector disposing of ComputeBuffer` и `PlayerConnection::Cleanup[d3d12]`. Оно есть и при выходе из 1-1, и при закрытии из Home до запуска боя. Оба журнала находятся рядом с BuildReport (`manual-player.log`, `baseline-home-player.log`). Источник графического буфера ещё не установлен.
