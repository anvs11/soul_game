## Plan of Work


Первый результат — безопасная модель попытки. Состояния Booting/Home/LoadingArena/InArena/ReturningHome/Faulted позволяют отвергать повторные команды. Асинхронный загрузчик сообщает завершение один раз. Неудача даёт понятное состояние Faulted; можно запросить повторный переход домой. Окончание собирается за кадр и разрешается один раз, Defeat сильнее Victory и Abandoned.

Второй результат — композиция Unity. Bootstrap хранит единственный постоянный корень, создаёт координатор и SceneFlow. Последний асинхронно грузит сцены, один раз находит корневой FlowScreen и явно передаёт координатор. Экраны подписываются при привязке и снимают подписки при отключении. Смена сцены не генерирует игровой итог.

Третий результат — сцены и передача. Команда меню проверяет сохранность открытых сцен и коллизии, создаёт новые сцены аддитивно, сохраняет их через Unity и возвращает исходную открытую сцену. Build Settings получает Bootstrap первым; прежние прочие сцены сохраняются выключенными. Сборка основы использует новые три сцены и уникальную папку, не изменяет старые сборки.


## Concrete Steps


Из W статически проверить JSON .asmdef, новые имена и отсутствие изменений в BaselineSmoke, контракте и пакетах. Не запускать повторно Install.ps1: пользовательский BaselineReport отличается от шаблона и должен сохраняться.

В Unity после окончания импорта: Game → Setup → Create foundation scenes. Если есть несохранённые сцены, сохранить их вручную и повторить. Затем открыть Assets/_Game/Scenes/Bootstrap.unity, нажать Play и пройти дом → пустая арена → проверочный выход → дом десять раз.

Window → General → Test Runner: EditMode Run All, затем PlayMode Run All. Конкретное количество и результаты записываются после запуска; ноль проверок — ошибка приёмки. PlayMode требует созданные сцены в Build Settings.

Game → Build → Build S1 foundation Windows создаёт новую Game/Builds/Foundation/Windows/<buildId>/Game.exe и foundation-build-summary.txt. Запустить exe вручную и повторить цикл. Команды сами не запускаются при импорте.


## Validation and Acceptance


EditMode доказывает отказ двойному старту, один возврат при повторном завершении, приоритет смерти, десять попыток с новыми идентификаторами, восстановление после ошибки и игнорирование callback после Dispose. PlayMode проверяет настоящие переходы, кнопки, один корень сервисов и EventSystem, уничтожение прежних экранов и повторный Bootstrap.

Ручная приёмка — десять повторов в Editor и новой Windows-сборке, без красных ошибок, с единственной камерой/корнем сервисов в каждом устойчивом состоянии. Пустая арена прямо сообщает отсутствие героя и врагов. После проверки оба участника открывают одну основу с теми же версиями. Android, iOS, HUD, бой и награды здесь не объявляются готовыми.


## Idempotence and Recovery


Новые исходники создаются только при отсутствии пути. Существующие сцены команда не заменяет: совпавшая сцена проверяется и остаётся нетронутой; при несовместимом содержимом выдаётся ошибка. Частично созданный комплект дополняется после устранения причины. Не удалять .meta, Library, чужие изменения или сборки.

При неудаче перехода состояние Faulted показывает ошибку, повторный запрос домой не создаёт вторую загрузку. Dispose отключает запоздалые callback. Каждый запуск восстанавливает Time.timeScale=1. Код не читает профиль игрока и не пишет сохранения.

## Interfaces and Dependencies


RunCoordinator(ISceneFlow) предоставляет Begin, StartRun(RunRequest), FinishRun(RunOutcome), ResolvePendingFinish, RetryHome, Changed и Dispose. RunRequest выбирает единственную CombatSandbox и несёт seed без генерации. ISceneFlow.TryLoad(string, Action<bool,string>) при false не вызывает callback, при true завершает его ровно один раз. GameBootstrap разрешает pending finish в LateUpdate.

FlowScreen.Bind(RunCoordinator) создаёт UI один раз, подписывается и сразу отображает состояние. OnDisable/OnDestroy снимают подписки. SceneFlow имеет Unity-ссылку на координатор только после Initialize. Используются имеющиеся Unity UI, Input System и Test Framework без новых зависимостей.
