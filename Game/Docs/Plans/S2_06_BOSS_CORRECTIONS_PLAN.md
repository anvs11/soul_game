# Скорректировать урон босса, однократный призыв и скорость героя


ExecPlan по .agent/PLANS.md, 15 ноября 2026, база0306681, ветка feat/stage2-arenas. Пользователь принял бочку и просмотрел босса, попросил усилить пули, однократные подкрепления и небольшое ускорение героя. Unity закрыта.

## Purpose / Big Picture


Очередь босса становится опаснее. Его пуля наносит15 вместо10, защитный интервал после принятого попадания пули.1с вместо штатных.5с. Пара одновременных пуль по-прежнему может засчитаться как одно попадание, но последовательная очередь чаще проходит защиту. Герой двигается5.5 вместо5, прирост10%. Двое щитоносцев появляются один раз при первом кувырке второй стадии. Четверо появляются один раз после первого кувырка третьей стадии.

## Surprises & Discoveries


DamageReceiver даёт.5с защиты после принятого урона, поэтому множество видимых пуль может отфильтровываться, а первые попадания уходят в броню. SpawnMinions сейчас вызывается при каждом старте кувырка, а лимит4 лишь ограничивает число живых. Простое изменение HP/урона не исправляет повторное пополнение.

## Decision Log


15 ноября — DamagePacket получает optional protectionSecondsOverride, DamageReceiver применяет его для следующего защитного окна. Пакеты без override используют прежний protectionSeconds. Босс отправляет15/.1, обычный бой сохраняет прежние данные. Небольшое ускорение5→5.5 записывается в Player prefab и default ActorMotor2D.

15 ноября — флаги призыва сохраняются весь срок жизни экземпляра, не сбрасываются при Initialize/disable. Стадия2 призывает2 при начале первого соответствующего кувырка, стадия3 призывает4 после завершения первого соответствующего кувырка. Выжившие двое остаются, поэтому лимит живых повышается до6. При перескоке сразу на стадию3 появляются только её4, не проигрывается пропущенный призыв стадии2. Стены/занятость точки могут ограничить безопасный спавн, повторные кувырки не компенсируют потери.

## Context and Orientation


Combat/DamagePacket.cs передаёт урон, Actors/DamageReceiver.cs фильтрует защитное окно. AI/PoliceBoss.cs управляет циклом и собственными миньонами, PoliceBossDefinition и одноимённый asset задают баланс. Player.prefab сериализует speed5, поэтому одного default в ActorMotor2D недостаточно. Tests/PlayMode/InputMovementTests.cs наблюдает прежнюю скорость5, его числовые ожидания обновляются для нового согласованного default без удаления assertions.
