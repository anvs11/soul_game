## Decision Log

S4-03A18 ноября: ограниченное размещение повторно использует точки между волнами, поскольку волны строго последовательны; внутри одной волны круги не пересекаются. Вместимость точек ограничивает разбиение на1–2 волн, запрос неподходящему банку даёт Failure. MapVersion входит в ключ комнатного PRNG; глобальный график пар зависит только от seed и algorithm/content, чтобы не зависеть от посещения/геометрии отдельных стадий.


Решение 2026-11-18: контракт — новый Game.Encounters, отдельные версии algorithm/content/map, без изменения Generation/RunGenerator и v0.1 CombatSnapshot. Причина: фиксированная география имеет иной смысл, чем Stage 3 ModuleId.

Решение 2026-11-18: локальные координаты точки отсчитываются от центра комнаты; клетка = 1 world unit. DelaySeconds каждой волны отсчитывается после завершения предыдущей волны, scaled time. Первая волна — после безопасного входа. Так временное alive=0 при задержке явно не означает Cleared.

Решение 2026-11-18: призывы заранее резервируют конечные обязательства SpawnId; они входят в pending до материализации. Невыполненные слоты отменяются только явным сигналом смерти владельца/окончания способности с известным OwnerSpawnId. disable/unload не убийство и не успех. Предлагаемый технический максимум для гранатомётчика — 4 слота на экземпляр до отдельного боевого плана; число не объявляется пользовательским балансом.

## S4-03A — исполняемый план выбора столкновений

Основа7cb1623, отдельный worktree Game/TestResults/s4-plan-review-20261118. Контракт S4-01 и исходный пример сохраняются. Milestone1 добавляет EncounterPlanner:IEncounterPlanner и чистый EliteStageSelection график1-1/1-2/1-4. Milestone2 добавляет EditMode риски детерминизма/ошибок, затем компиляцию и полные регрессии. Успех — тот же seed/версии/карта даёт тот же сериализованный состав всех5 комнат, изменение порядка коллекций/Unity Random/вызовов ничего не меняет; разные seed дают несколько составов; отказ не содержит Plan.

Решение до кода: алгоритм1/контент1, SplitMix32 с unchecked uint, стабильный FNV-1a над явными low/high bytes UTF-16 RoomId/MapId. Коллекции сортируются ordinal. Локальный поток каждой комнаты зависит от seed/версий/RoomId/попытки, география не меняется. Не более20 попыток, не более1024 узлов поиска точек на комнату/попытку. Негодный банк/исчерпание возвращает Failure с seed/версиями/причиной; fallback остаётся отдельным S4-03B.

Три вида elite переставляются локальным PRNG; пары для трёх стадий циклические (a,b),(b,c),(c,a), дубликат берётся из своей пары. График строится до посещений, покрытие всех3 обязательно. MapId фиксирует стадию1-1/1-2/1-4; отдельный CreateEliteSchedule(seed,g,c) отдаёт весь график. Количество ordinary выбирается в min/max/cost, состав циклически из перемешанных3 типов (при count>=3 все3),1–2 волн; combat_b обязательно2 при допустимом бюджете, иначе явный отказ. Следующая задержка2 scaled seconds после завершения предыдущей волны по S4-01, первая0. Это технические данные прототипа, не новые настройки runtime-баланса. Для точек соблюдается AllowedTypes/clearance/разделение кругов, hero_entry не используется и исключается контакт с ней. Максимум4 reserved слота на grenadier в пределах MaxSummons, прежнее предложение S4-01, фактических слизней нет.
