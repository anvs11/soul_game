## Готовность и область

Реализован путь Bootstrap → Home → CombatSandbox → результат в Home → обычный Home → новая попытка. Одна фиксированная арена, герой, три зомби, пистолет/нож, HUD, выход после зачистки, смерть, пауза и экранные элементы управления. Пользователь подтвердил ручную проверку Windows Editor, границ и экранных контролов. Автоматическая проверка отдельного exe описана ниже; она использует настоящие команды и боевые системы, но не заменяет ручной осмотр standalone/UI или Android-устройство.

Общая Stage 1 остаётся на межплатформенной/взаимной приёмке. Не подтверждены Mac у получателя, физический Android и независимое ревью У1 новых изменений роли 2. Это не полный MVP: несколько поведений врагов, босс, пять сегментов и постоянный прогресс ещё предстоят. Генератор, магазин, сохранения и сеть не добавлены.

`Game.Editor.BuildCommands.BuildStage1Windows` и `BuildStage1Android` задают собственный точный список сцен: `Assets/_Game/Scenes/Bootstrap.unity`, `Home.unity`, `CombatSandbox.unity` в этой последовательности. BaselineSmoke, CombatDev_A и Stage1ArenaPreview в них не включены. Каждая попытка получает новый UTC timestamp + случайный суффикс; каталог не переиспользуется. Успех определяется `BuildReport.summary.result`, не наличием exe/apk и не только кодом Unity. В каждой папке сохранён build-report.json с фактическими ошибками/предупреждениями. Обе сборки Development, APK предназначен для локальной отладки, не для публикации.

## Настоящий Windows Player

Запуск exe с `--stage1-smoke -screen-width 1280 -screen-height 720 -windowed -logFile <build-folder>/smoke-player.log`. Development-only runner создаётся только при явном флаге, в обычном запуске не действует. Он ждёт Bootstrap/Home, нажимает существующие кнопки Home, передаёт PlayerCommand через IPlayerInputSource в ActorMotor2D. Десять побед получены реальной стрельбой с расходом патронов и реальным движением к выходу; здоровье врагов не назначается напрямую. Затем без сопротивления получена настоящая смерть от зомби. Каждый раз проверяются новый RunId, три врага, свежие 100 HP и 8 патронов, один GameBootstrap, отсутствие активных Projectile в Home, экран результата и timeScale=1. В первом цикле проверены пауза/продолжение.

Итоговый JSON: `Game/Builds/Stage1/Windows/20261114-203727-d470e717/smoke-33d04057c02f48adb2d0be18b1f11c91/result.json`. passed=true, victories=10, defeats=1, loggedErrors=0, exit=0. Лог рядом в smoke-player.log. Runner считает все Error/Exception/Assert за время прогона и не принимает результат при их наличии. Никакая его проверка не считается ручным прохождением игры человеком.

## Открытая приёмка

Windows: пользователь вручную проверял Editor; отдельный Player проверен автоматическим боевым циклом. 14 ноября пользователь подтвердил ручное прохождение финального Windows exe: всё работает. Аппаратный gamepad и разные соотношения сторон отдельно не подтверждены. Нет профилирования нагрузки и большого числа снарядов.

Android: APK собран, но телефон отсутствует по ответу пользователя. Не проверены установка/старт, два настоящих пальца, системные жесты, сворачивание/возврат, Safe Area конкретного экрана, производительность и нагрев. Для последующей приёмки установить именно финальный APK, пройти из Home движение+атаку двумя пальцами, отпустить один палец, свернуть при удержании обоих, вернуться и убедиться в паузе/сбросе, победить/погибнуть и повторить. Зафиксировать модель, Android, buildId, результат и лог при ошибке. До этого mobile acceptance открыта.

Mac: запуск проекта/нужная нативная сборка на компьютере У1 не подтверждены; Windows результат их не заменяет. Отчёт ROLE_1_STATUS и S1_06_REVIEW сохранён как исторический, его прежние числа 23/16 — не новые результаты.

Взаимное ревью: роль 2 проверила полученный бой; У1 ещё должен независимо просмотреть новую интеграцию и подтвердить её на своей платформе. Никакое внешнее сообщение ему не отправлялось.
