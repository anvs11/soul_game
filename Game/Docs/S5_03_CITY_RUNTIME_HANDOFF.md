# S5-03. Добыча и торговля City

Ветка `feat/stage5-progression`. [Реализация сессии](../Assets/_Game/Scripts/Progression/CityProgressionSession.cs) · [Дополнения к контракту](../Assets/_Game/Scripts/Contracts/CityProgressionContracts.cs) · [EditMode](../Assets/_Game/Tests/EditMode/CityProgressionTests.cs) · [PlayMode](../Assets/_Game/Tests/PlayMode/CityProgressionCombatTests.cs)

S5-03 поставляет исполняемую сессию и боевые множители. UI, Bootstrap и переходы карты подключает У2. Кристаллы, подтверждённые зачисткой, сохраняются в экземпляре сессии между попытками. Запись на диск, загрузка после перезапуска и предложение Home приходят в S5-05.

## Подключение к карте

Создайте один `CityProgressionSession(() => Time.timeAsDouble, confirmedCrystals)` на профиль. Вызовите `StartRun` один раз с RunId от RunCoordinator, seed и каталогом точек всего City. Допускается пустой каталог. Порядок входного списка на результат не влияет. `Run.Npcs` показывает полный, уже рассчитанный план. Для построения входов фильтруйте его по StageId текущей сцены. Ожидаемые StageId — `1-1`…`1-5`.

Свяжите `PlayerCombatFacade` через `BindCombat`. Перед подтверждением покупки Барыги передайте `hero.EquippedWeaponId`. При переносе героя в следующий игровой уровень вызовите `EnterStage`, перенесите ID сохраняемых экземпляров через `newHero.BindProgressionWeaponIds(oldFirearmId, oldBladeId)` и привяжите новый фасад. Скопируйте только ID экземпляров, которые действительно остались у героя. Для заменённого оружия используйте новый ID. Сессия снимает свои множители со старого фасада. При загрузке другой сцены монеты и состояние NPC сохраняются, а предметы с земли прежней стадии исчезают. Повторный вход в интерьер не вызывает `StartRun` или `EnterStage`.

Из `RoomController.EnemyDefeated` передайте `ConfirmEnemyDeath` до `Cleared`. SpawnId уникален во всей попытке. Если карта переиспользует имя при переходе, добавьте к нему устойчивый StageId, сохранив сегмент `/summon/`. Для одного NPC или предмета ключ из снимка действует до конца попытки. Для каждой комнаты также закрепите уникальный checkpointIndex на весь City. Передайте `ClearCheckpoint` только по подтверждённой зачистке. Зачистка автоматически включает незабранные кристаллы этой комнаты и завершает эффекты Диллера.

`CollectLoot` принимает PickupId. Патроны используют `TryAddReserve`, а непоместившаяся часть остаётся в той же записи. `CollectSupply` принимает стабильный ID находки, вид `Medkit` или `Armor` и количество из каталога карты. Он использует `TryHeal` или `TryRepair` и расходует предмет целиком после любого положительного восстановления. При полном ресурсе оставьте предмет на месте или в рюкзаке. Хранение аптечки в рюкзаке и выдачу брони из контейнера по-прежнему ведёт карта.

Отказ от диалога или выход из интерьера не вызывают команду покупки. После оплаты отсчитывайте срок по `ReadyAtGameTime` в общих игровых часах, в том числе пока игрок находится на улице. Вызовите `CompleteNpcService` по таймеру, повторив тот же ключ после `ServiceNotReady`. Предмет остаётся доступен до добровольного применения. Для пузырька вызов `DrinkBottle` выполняется отдельно от оплаты. До следующей новой зачистки каждый употреблённый пузырёк даёт множитель движения. Для двух пузырьков множители перемножаются.

Вызывайте `FinishRun` до уничтожения фасада, с исходами `Defeat`, `Abandoned` или `Victory`. Снимок Home получает `LastRun` с итоговыми монетами и заработанными подтверждёнными кристаллами. Итоговые монеты показываются в отчёте и не переходят в новую попытку. При новом запуске создаётся новый RunId.

Сессию вызывайте с игрового потока Unity. Если синхронный обработчик изменения боевых ресурсов попробует изменить сессию внутри другой команды, он получит `RetryableFailure / OperationInProgress` и сможет повторить запрос после завершения первого вызова.

## Стартовый баланс

Обычный зомби даёт 5–10 кристаллов, мини-босс — 75, тяжёлый босс — 270, малый зомби — 11–15. Для раннего City тяжёлый босс и малый зомби представлены идентификаторами `heavy_boss` и `small_zombie`. Призванные мини-слизни добычи не дают. Стрелок с вероятностью 50% роняет 8 патронов. Каждый зомби независимо от патронов с вероятностью 30% даёт 1–3 монеты, равновероятно для каждого количества.

Барыга берёт 3 монеты. Срок — 2 секунды игрового времени. Пистолет получает множитель интервала выстрела 0,8, нож — множитель урона 1,25. Диллер берёт 4 монеты. Полезная ветвь даёт скорость движения ×1,2 с вероятностью 70%, вредная — ×0,8 с вероятностью 30%. На скорость кувырка и отбрасывания эти эффекты не влияют.

Расчётный каталог — пять стадий, в каждой по три комнаты с 6–8 обычными зомби. На 1-1, 1-2 и 1-4 по три мини-босса, на 1-3 и 1-5 по одному тяжёлому боссу. Проверочный расчёт по 2048 seed повторил алгоритм бросков из C# и дал 49,91% выпадений патронов, 29,96% выпадений монет, в среднем 69,44 монеты и 2002,76 кристалла за City. Полезная ветвь пузырька составила 68,61% на 1386 покупках. Это расчёт синтетического каталога. Основной игрок может пропустить монеты на карте, поэтому 69,44 — средний объём выпадений до подбора и трат.

## Проверка в Unity

В Unity **6000.3.28f1** откройте проект `Game` → **Window → General → Test Runner**. Выберите `Game.Tests.CityProgressionTests` в EditMode и `Game.Tests.CityProgressionCombatTests` в PlayMode. EditMode проверяет сессию, повтор событий, покупки и частоты выпадения. PlayMode проверяет, что игрок использует боевые множители и возвращается к базовым значениям после снятия.

Для запуска из корня репозитория закройте интерактивный Unity и выполните команды последовательно. Для каждого повторного прогона используйте новый каталог отчётов.

```sh
mkdir -p Game/TestResults/S5-03
"/path/to/Unity" -batchmode -nographics -projectPath "$PWD/Game" \
  -runTests -testPlatform EditMode -testFilter Game.Tests.CityProgressionTests \
  -testResults "$PWD/Game/TestResults/S5-03/EditMode.xml" \
  -logFile "$PWD/Game/TestResults/S5-03/EditMode.log"
"/path/to/Unity" -batchmode -nographics -projectPath "$PWD/Game" \
  -runTests -testPlatform PlayMode -testFilter Game.Tests.CityProgressionCombatTests \
  -testResults "$PWD/Game/TestResults/S5-03/PlayMode.xml" \
  -logFile "$PWD/Game/TestResults/S5-03/PlayMode.log"
```

Проверочный расчёт выполнен 22 ноября 2026. Прогон EditMode и PlayMode в Unity в этой сессии не выполнялся.
