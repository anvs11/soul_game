## API и поведение

Сигнатуры сохранены: `new RunGenerator().Generate(int seed, StageCatalog catalog, int generatorVersion, int contentVersion)` → GenerationResult; `new LayoutValidator().Validate(RunLayout layout, StageCatalog catalog)` → ValidationResult. Типы/конструкторы/копирование коллекций — S3_01_LAYOUT_CONTRACT.md. Публичные константы RunGenerator: SupportedGeneratorVersion=1, SupportedContentVersion=1, новая MaxAttempts=20. Версия1 закончена проверкой кандидатов; PRNG и первый кандидат для ранее валидных каталогов не менялись.

Validate требует ровно5 сегментов в порядке Index1..5, известные Id, Combat в первых4 и Boss в последнем, поддерживаемые версии. Для каждого выбранного модуля проверяются проходимый вход, доступный выход и каждая точка появления; Combat/Boss обязаны иметь хотя бы одну SpawnCell. BFS использует4 соседние клетки без диагоналей и перехода через край строки. Разметка y*Width+x, единица сетки и требования clearance остаются прежними. У босса Exit — логическая конечная клетка, физическая дверь не требуется.

Размеры/длина Walkable/границы/enum/null/дубликаты Id уже проверяются неизменяемыми конструкторами. Эти гарантии не ослаблялись: неверная форма возвращается вызывающему как ArgumentException/ArgumentOutOfRangeException/ArgumentNullException на создании данных, а не как успешная генерация. Null catalog/layout и неположительные версии методов также остаются исключениями программного использования. Runtime-адаптер У2 должен перехватить такие ошибки экспорта и показать отказ до запуска. Семантические ошибки допустимого объекта данных (неизвестный модуль/заблокированные точки/плохой состав/неподдерживаемые положительные версии) дают причины ValidationResult или Failure без Layout. Сырых повреждённых mutable-массивов внутри генератора нет.

Проверяется выбранный маршрут, а не достижимость каждого невыбранного варианта банка. Каталог может содержать непроходимый вариант, который будет отклонён при выборе; иначе восстановление из банка альтернатив не имело бы смысла. Entry/Rest вне пятёрки не валидируются этим маршрутом — У2 проверяет их при собственной загрузке. Проходимость реальных collider, радиус босса2, места призыва и ограничения прямолинейного AI остаются отдельной проверкой У2; навигация AI не добавлена.

## Конечный подбор

Generate сортирует Combat/Boss по Ordinal и использует прежний SplitMix32 с локальным состоянием. Каждый из максимум20 кандидатов получает4 Combat с повторениями и1 Boss, проходит ValidateKnown (тот же валидатор, что публичный Validate). На первом валидном — IsSuccess=true, UsedFallback=false. Не выполняются20 попыток, если первая или вторая уже успешна. Нет глобального состояния/мутации входа.

После20 отказов создаётся ровно fallback `street_a,street_b,street_c,street_a,street_boss`. Эта21-я проверка является единственной проверкой фиксированного fallback, не дополнительной случайной попыткой. Неизвестные fallback Id, неверные Kind и непроходимые клетки ведут к Failure(Layout=null,UsedFallback=false). Валидный fallback даёт IsSuccess=true/UsedFallback=true. Fallback проверяется, когда он нужен; его отсутствие не мешает успешному случайному маршруту с другими валидными Id. Недостаток Combat/Boss и неизвестные положительные версии дают Failure без подбора (attempts=0).

Diagnostic включает seed/generatorVersion/contentVersion/attempts. Успех — `validated`; у fallback дополнительно последняя причина отклонения и `validated fallback`; отказ — `fallback invalid` с причинами. Проверки отдельных модулей кешируются по Id только внутри одного Generate; кеш не сохраняется между seed/каталогами. Прямой Validate создаёт свой новый кеш. BFS по конечной сетке посещает каждую клетку максимум один раз, подбор ограничен20 кандидатами; отбраковка чисел внутри PRNG не является попыткой подбора маршрута.

## Маленькие примеры

Сетки ниже записаны снизу вверх (y0,y1,y2); `.` — true, `#` — false. Размер3×3, Entry(0,0).

| Сетка y0 / y1 / y2 | Exit и Spawn | Ожидание |
| --- | --- | --- |
| `... / ##. / ...` | Exit(0,2), Spawn(2,1),(1,2) | Валидно: путь обходит стену справа. |
| `... / ### / ...` | Exit(2,2), Spawn(1,0) | Невалидно: закрыта средняя строка. |
| `... / .## / .#.` | Exit(0,2), Spawn(2,2) | Выход доступен, но spawn изолирован. |
| `.## / #.# / ##.` | Exit(2,2), Spawn(1,0) | Диагональ не образует путь. |

Пример успеха API: создать через конструкторы шесть Id из S3-01 с открытыми сетками и хотя бы одной SpawnCell у Combat/Boss, вызвать Generate(123,catalog,1,1). Первый кандидат валиден, UsedFallback=false, layout содержит5 сегментов; Validate(layout,catalog).IsValid=true. Пример отказа: заменить сетку street_boss на `.../###/...` с Exit(2,2). При единственном таком Boss все20 кандидатов и fallback невалидны, IsSuccess=false/Layout=null, Diagnostic содержит seed123, версии1/1, attempts20 и причину недостижимого выхода. В интерфейсе показывать отказ, сцену боя не загружать.

Для воспроизводимого fallback тест создаёт3 открытых Combat a/b/c, открытого street_boss и64 вариантов bad_00..bad_63 с закрытой средней строкой. Для seed0 каждая из20 последовательностей содержит bad-вариант; фиксированный fallback открыт. Для раннего восстановления достаточно одного `bad` плюс3 открытых Combat: seed2 отвергает первый кандидат, второй даёт b,b,a,a,boss, attempts=2/UsedFallback=false. Это естественные выборы PRNG, без искусственного внедрения ошибки.
