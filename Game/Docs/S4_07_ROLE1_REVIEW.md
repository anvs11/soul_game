18 ноября 2026. **Данные каталога V2 подтверждены для 1000 seed. Интеграция S4-06 и ручная проверка открыты.** После fetch `origin/main` и `origin/feat/stage4-map` указывают на `7cb16232d21b59c333de6e043c7dc611c39809c2`. Экспорт У2 добавлен в `3567960c147dd02fe2b7ef021c575cbb7b1742c7`. В полученных ветках, истории и доступных рабочих копиях `S4_06_RUNTIME_HANDOFF` отсутствует. Коммит интеграции не получен. Ревью текущих данных ведётся в локальной `feat/stage4-encounters` с незакоммиченным planner S4-03A/B. На момент сверки planner ещё не входил в командный main.

## Краткая передача У2

Можно брать `EncounterPlanner`, его валидатор и каталог V2 для интеграции. C# проверил 1000 seed на G1/C1/Map2/Geometry1. География фиксирована, в `combat_b` гарантированы две волны, элита планируется как три экземпляра двух видов. Условие `Cleared` должно учитывать живых детей и ожидающие слоты. Полный API и семантика волн в [S4_03_ENCOUNTER_HANDOFF.md](S4_03_ENCOUNTER_HANDOFF.md).

Общий маршрут пока диагностический. A0 движения прошёл отдельные Mac Editor тесты 118/120 на локальной ветке. A1 и S4-05B локально без Unity-прогона, A2/A3 пока в планах. Для следующей проверки У1 нужны ветка и полный SHA интеграции, `S4_06_RUNTIME_HANDOFF`, способ задать seed в 1-1 и экспорт с фактической проверкой prefab/укрытий/детских точек. Bootstrap и устройства остаются открытыми.

## Наблюдения для У2 и воспроизведение

- **Интеграция на полученной основе ещё диагностическая.** Открыть Bootstrap → Home → «1-1: постоянная карта · прототип S4-02». В `HomeScreen.CreateFixedStreetButton` кнопка вызывает `RunRequest.FixedStreet1_1()` со значением seed 0 по умолчанию. `StreetMapScreen.CreateRooms` строит `EncounterExample.CreateFixedPlan`, а `elite` получает два `SandboxEnemy`. `RoomController.Configure` на этой основе принимает `SandboxEnemy[]`. Поэтому этот маршрут не может подтвердить 1000 runtime seed, целевой состав элиты, кувырок или подборы. После handoff сверить источник seed, формирование экземпляров по EnemyTypeId и использование ровно одного registry.
- **Экспорт элиты остаётся на proxy.** В JSON `elitePrefabsCertified=false`. Для `elite_0..2` доказана свобода круга 1,0. Призыв детей пока представлен бюджетом, а экспорт не содержит сертифицированные детские позиции. После добавления prefab и укрытий передать новый SHA/GeometryVersion, географию и проверку ширины тарана 3, безопасных точек телепорта, призывов и непрерывных путей. На seed 2 умертвить одного гранатомётчика после призыва и проверить, что его живые дети ещё обязательны, а pending слоты второго владельца не затронуты. Включить отказ для занятой точки и убедиться, что он не даёт ложный Cleared.
- **Приёмка нового runtime после передачи hash.** С чистой попытки пройти точки (10,0) → (23,0) → (23,12) → (23,24) → (37,24) → (51,24) → (65,24) → (83,24). Проверить полное пересечение створов перед закрытием. В `combat_b` дождаться нуля живых в первой волне, поставить паузу на 2 секунды реального времени, проверить сохранённый остаток таймера, закрытые двери и отсутствие Cleared. Снять паузу и закончить вторую волну. Проверить три основных экземпляра двух типов на seed 0/2/123 и геометрию при повторе seed 0.
- **После боя проверить один Interact.** Выполнить кувырок к стене, повторный запрос на cooldown и паузу. С пустой бронёй/неполным HP и запасом ниже максимума проверить подборы всех трёх типов и отражение ресурса в HUD. На полном ресурсе предмет остаётся. В кадр сбора подать второй Interact и проверить отсутствие двойного начисления или преждевременного выхода. После четырёх Cleared подтвердить ровно один портал, отсутствие выхода издали/на паузе и возврат в Home при близком Interact. Отдельно проверить гибель и новую попытку без старых объектов/подписок. Порядок подбора и выхода должен быть указан в handoff владельца.

Изменений сцен, Core, общего status У2 или runtime-кода в этом ревью нет. Воспроизведения выше подготовлены для У2 и доступны вместе с этим отчётом.
