## Запуск и поведение

Bootstrap → Play → кнопка постоянной карты 1-1. Вход безопасен. После полного пересечения входа в combat_a/b/c закрываются оба прохода этой комнаты. После последней обязательной смерти проходы становятся зелёными/проходимыми. Повторный вход в ту же зачищенную комнату не создаёт противников и повторного Cleared.

Итого те же шесть существующих обычных врагов, их HP/урон и стартовые 100HP/30armor/8+16/нож не меняются. В промежутке combat_b alive=0, pending=1: двери остаются закрытыми. Элитная комната пока НЕ ГОТОВА, три оранжевые метки не являются противниками. После трёх обычных Cleared нет победы/награды/портала. ## API и состояния

`RoomEncounterState(RoomPlan)` — чистый конечный реестр SpawnId. Свойства Phase/WaveIndex/DelayRemaining/PendingCount/AliveCount/IsWaveDue; методы Begin(), Tick(scaledDeltaTime), CanMaterialize(id), MarkMaterialized(id), ConfirmDeath(id), CancelUnmaterializedSummons(ownerId), Cancel(). Phase: Dormant → Waiting → Fighting, затем следующая Waiting или Cleared. Cancelled — отдельный терминальный исход без награды. Неизвестные/повторные SpawnId не уменьшают счёт. Pending включает все ещё не появившиеся основные цели и зарезервированные дочерние слоты. Конструктор отвергает повторный SpawnId даже между разными волнами.

Задержка каждой следующей волны начинается после закрытия всех обязательств предыдущей; первый FixedUpdate входа не вычитает время из первой задержки. Вызов Tick(0) не ускоряет ожидание. Переход в Cleared требует исчерпания всех волн/pending/live. После Cancel таймер не продолжается, счёт невыполненных обязательств сохраняется для диагностики. Alive/disable/Destroy не трактуются как убийство.

`RoomController.Configure(string runId, EncounterRoom description, RoomPlan plan, PlayerCombatFacade player, TargetRegistry registry, SandboxEnemy[] actors, DoorController[] gates)` сначала валидирует данные. Пока adapter поддерживает только обычные melee, каждый primary SpawnId имеет отдельный существующий actor. Этот предел явный; не подменять elite melee-заглушками. Координаты спавна = room center + локальная точка. Перед активацией OverlapCircle проверяет свободное место от World/ActorIdentity; при помехе SpawnId остаётся pending и попытка повторяется, двери не открываются. Пул/новый prefab и боевой ресурс при этом не расходуются. Никакого поиска всех объектов сцены каждый кадр нет, списки физического запроса переиспользуются.

Контроллер подписывает каждую живую цель на реальный Died, подтверждает её IsDead и снимает подписку после первой подтверждённой смерти. OnDisable/OnDestroy самого контроллера и Leave/death героя вызывают Cancel: таймеры прекращены, подписки сняты, актёры отключены, Cleared не выдаётся. Cancelled-встреча не запускается повторно. Неподтверждённое исчезновение отдельной цели оставляет обязательство/закрытые двери — это не скрытый успех; пользователь может выйти домой.

`RoomController.Cleared` — Action<RoomController>, публикуется один раз с RunId/RoomId, открывает двери. `StreetMapScreen.RoomCleared` — Action<string,string>, дополнительно исключает повторный RoomId в своём RunId. `StreetMapScreen.ClearedCount` считает только три диагностические ordinary-комнаты. Это будущая точка выдачи награды по паре RunId/RoomId. Фактической награды в S4-04A нет; тестовый счётчик подписчика доказывает однократность события, а не готовый pickup.

Конечные призывы по S4-01 поддержаны в реестре: owner/summon/index заранее pending; TryMaterializeSummon(ownerSpawnId,index,IEnemyTarget) у RoomController привязывает уже инициализированного У 1 живого ребёнка к известному слоту. Резерв нельзя материализовать до появления владельца или дважды, индекс/владелец должны существовать. CancelUnmaterializedSummons отменяет только неиспользованные слоты конкретного уже появившегося владельца. Реальная смерть владельца вызывает такую отмену, но живые дети остаются обязательными до их смерти. Это проверенная семантика данных, не готовые мини-слизни/elite-spawner: их создаст последующий S4-05/06 адаптер.
