# S2-03A — отдельный прыгун

15 ноября 2026. Пользователь передал выполнение части У1 агенту У2. База 1595d72, ветка feat/stage2-arenas. Выполнена только часть A; стрелка и полной S2-03/S2-04 нет. Это реализация и собственная проверка, не независимое ревью У1.

## Поведение и API

Scripts/AI/JumpingEnemy.cs реализует Idle/Chase/Windup/Dash/Recovery/Dead. Отдельный JumpingEnemyDefinition хранит настройки, HP экземпляра находится в DamageReceiver. Configure(definition, worldMask, damageMask) до первой активации; Initialize(TargetRegistry, Transform player) связывает реестр/героя и сбрасывает подготовку/память. На свежем неактивном ресурсе DamageReceiver настраивается отдельно: definition.Health/0/0. Runtime Configure не перезаписывает уже начатую жизнь. OnDisable отписывается, прекращает движение и сбрасывает атаку, повторное включение не продолжает старый рывок и не оживляет погибшего.

Параметры: HP 30, ChaseSpeed 2.5, дальность старта <=4, подготовка .6 с, DashSpeed 12, DashDuration .3 с (до 3.6 единицы), Recovery 1 с, урон 10, HitRadius .4, принятый толчок героя 3 клетки. Обнаружение 8/11/2 через существующий EnemyPerception; маска укрытий World. Все времена scaled, пауза останавливает подготовку/рывок/восстановление. Направление фиксируется на старте подготовки и дальше не отслеживает движение героя. Жёлтая полоса показывает направление, цвет отличает подготовку/восстановление. Это простые заглушки, не законченная анимация прыжка.

Dash проверяет путь Rigidbody2D до стены, применяет реальный DamagePacket только к назначенному противнику другой фракции, максимум одну попытку за рывок (включая отказ из-за неуязвимости). Несколько collider не дают повторного урона. Перемещение идёт физикой в FixedUpdate; игрок не выталкивается пассивным контактом с прыгуном. После смерти отключены движение/collider/видимость, Died однократный, registry очищается. Погибший при повторном включении не регистрируется.

## Один реестр и сохранённая основа

Новый внутренний Combat/IEnemyTarget : IDefeatable содержит ActorId, transform и isActiveAndEnabled. Это локальная типизация боевых целей, CombatContracts.cs v0.1 не меняется. MonoBehaviour автоматически предоставляет две последние свойства; SandboxEnemy и JumpingEnemy реализуют интерфейс. TargetRegistry хранит HashSet<IEnemyTarget>, Register/Unregister/Removed используют этот тип. AutoAimSelector.Select/CurrentTarget также возвращают IEnemyTarget; прежний WeaponController уже использует var и target.transform, его код не менялся.

EnemyTargets.Active сначала проверяет настоящий Unity Component != null, затем активность/жизнь: interface-null не маскирует уничтоженный Unity-объект. Отписки/повторная регистрация после включения registry и tie-break ActorId сохранены. Старые проверки автоприцела и ресурсов не изменены. ArenaController по-прежнему содержит SandboxEnemy[], смешанная тройка относится к будущей S2-04.

Исходные prefab Stage 1, CombatSandbox/Stage2CombatSandbox, Contracts, Core, UI, Packages, ProjectSettings не изменены. Ускоренный ближний .2/.06/.3 сохранён. Нет второго registry, скрытого SandboxEnemy на прыгунe или второй системы ввода.

## Ресурсы и ручная проверка

Новые Prefabs/Actors/Stage2/JumpingEnemy.prefab и JumpingEnemyDefinition.asset созданы Unity с .meta. Прыгун — отдельный prefab с Enemy-фракцией, Rigidbody2D Continuous, CircleCollider .4 и EnemyPerception. Диагностическая Scenes/JumpingEnemyPreview.unity — отдельная копия геометрии, с настоящим Player/HUD, одним registry и одним прыгуном. Runtime JumpingEnemyPreview связывает их, не создавая координатор. Сцена НЕ включена в Build Settings/обычные сборки, не является профилем маршрута/результатом. Исходные сцены У2 не сохранены поверх.

Для ручного просмотра открыть Assets/_Game/Scenes/JumpingEnemyPreview.unity напрямую и нажать Play. Герой зелёный слева, прыгун фиолетовый справа от него. WASD/стрелки — движение, Space — стрельба, Q — нож/пистолет. Дождаться жёлтой полосы и уйти поперёк направления: рывок идёт по старой линии. Остаться на линии: один урон и толчок. Увести его к серому укрытию: рывок не проходит стену. Застрелить во время подготовки/рывка — он прекращает бой; остановить Play и повторить — новый экземпляр. В preview нет меню паузы/результата; пауза таймеров проверена тестом, основные профили/меню сохраняют свои прежние проверки. Это диагностическая сцена для одного поведения, не замена Bootstrap-маршруту.

Визуальная приёмка пользователем пока открыта. Особенности: преследование прямолинейное, прыжок пока изображён рывком без вертикальной дуги; линия может быть слишком длинной/яркой, это предмет ручного просмотра. Бочки/оглушения/босса здесь нет.
